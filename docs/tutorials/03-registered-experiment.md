# Tutorial 03: write, validate and do not run a registered experiment

Goal: write an experiment file before any result exists, make the validator accept it, see the refusals, and know what happens at run time, without running anything.

Background: [LEARN.md Section 10](../../LEARN.md#10-back-testing-honestly-pre-registration-holdouts-attribution), [API_SPEC.md](../../API_SPEC.md) Sections 16.8 and 16.10, and the [runbook for a registered run](../runbooks/registered-experiment.md).

Do not run or sign `research/prereg/R5-FAM-001.yaml`. It is unsigned and no session of its seed base has been generated. This tutorial writes its own throwaway file under `target/tutorial/`, which git ignores.

## Step 1. Decide, in this order

1. **The question and its sign**, with the mechanism.
2. **The smallest difference worth finding**, in USD per session, before any pilot.
3. **The data.** A seed base nobody has read. Simulator v2 bases are whole millions of at least 28,000,000. 28,000,000 belongs to the acceptance tests, 29,000,000 to the pilot, 5,000,000 and 8,000,000 are spent, 31,000,000 is named by the unsigned family, and the superseded drafts named 30,000,000 and 32,000,000 to 38,000,000.
4. **What counts as failure**: guards as well as a p-value.
5. **What you will report if it is inconclusive.**

## Step 2. Write the config

Create `target/tutorial/TUT-001.config.yaml`:

```yaml
study: TUT-001
arms:
  baseline: "DeskProfile.simV2(DeskSettings.defaults())"
  cover_only: "baseline with StrategySwitches.coverPricing true"
seeds: {confirmation_base: 40000000, pilot_base: 29000000, minimum_sessions: 2000}
smallest_effect: {usd_per_session: 24000}
statistics: {block_sessions: 21, resamples: 2000, bootstrap_seed: 5}
guards: {quoted_share: 0.8, hit_rate: 0.25, client_dv01: 0.25}
```

Hash it, and the simulator's parameter file. **Run on 2026-11-24.** The first hash holds for exactly the lines above with a final newline.

## Step 3. Write the registration

Create `target/tutorial/TUT-001.yaml`:

```yaml
prereg_version: 2
status: draft_tutorial
id: TUT-001
title: "Tutorial: cover pricing alone against the baseline"
hypothesis: cover pricing alone raises mean session P&L, because the clamp sits below break-even
metric: total position P&L per session in USD, paired difference treatment minus baseline
baseline: baseline
treatments: [cover_only]
data_set:
  seed_base: 40000000
  sessions: 2000
  simulator_params: data/calibration/sim_v2_params.json
  simulator_params_sha256: 3e2159814ee4e9892ae0dba33f5f35fe0bdd33739df625ea4ae46162c1154fd4
prior_looks: []
test: two-sided paired t on the session differences, with a moving-block bootstrap interval
success_threshold: p below 0.05, interval above zero, every guard holds
assumption_band:
  preset: sim_v2_params
  parameters: [all_in_cost]
  points: [low, central, high]
author: tutorial reader
date: 2026-11-24
config: target/tutorial/TUT-001.config.yaml
config_sha256: 9522f754ddb61da6588920729ef8b8b6811b0917abef7130ff760a210757da35
```

`status: draft_tutorial` keeps it a draft, so the runner refuses it. Leave it that way.

## Step 4. Validate

**Run on 2026-11-24**; exit status 0.

```bash
PYTHONPATH=research python -m ratesresearch.prereg validate target/tutorial/TUT-001.yaml
```

```
target/tutorial/TUT-001.yaml: valid
```

The Java twin is `ExperimentRunner validate --prereg FILE` (read, not run here); for a draft it adds `(draft: validates, is not run)`. Valid means the rules hold. It does not mean that anybody approved the design or that the idea is good.

## Step 5. Break it, one rule at a time

**Run on 2026-11-24.** Each row is one edit, with the validator's text. Exit status 2 each time.

| Edit | What the validator says |
|---|---|
| `seed_base: 29000000` | `data_set.seed_base: seed base 29000000 is the pilot base: it sizes a confirmation set and is then discarded for inference`, and that the config's base differs |
| `seed_base: 5000000` | `data_set.seed_base: seed base 5000000 is spent: every session under 5000000 was generated by the old simulators and read by AUDIT-01 to AUDIT-26 (SIM_V2_DESIGN.md section 12)`, and that the config's base differs |
| `sessions: 500` | `data_set.sessions 500 is below the floor of 2000` |
| `treatments: [cover_only, baseline]` | `the baseline arm is also listed as a treatment` |
| `treatments: [v3]` | `config arms do not name the treatment 'v3'` |
| `points: [central]` | `assumption_band.points must be low, central and high (DR-008)` |
| `prior_looks` replaced by a `holdout` list | a dated file is read by the version 1 rules: `missing or blank key 'period'`, `missing or blank key 'fitting_period'` and `version 1 date key 'holdout' is not allowed in a session-seed design` |
| `sessions: "from the pilot"` with `status: signed` | `data_set.sessions must be an integer of at least 2000 once the file is not a draft` |
| `usd_per_session: 12000` in the config only | `config_sha256` (the registered hash) `does not match the config file` (the new hash); both are printed in full |

The last one is the point of the hash: the smallest difference cannot move after it has been written down.

## Step 6. What the runner refuses that the validator does not

Read from `ExperimentRunner`, not run. `run` prints `refused:` and the reasons, exits 2, and neither runs nor records anything, for:

- a registration whose status starts with "draft", or one superseded by another;
- a session count that is not fixed;
- an arm the factory cannot build;
- a band row the simulator refuses, or an excluded point that the simulator would in fact run;
- an output directory inside a git work tree;
- a checkout with uncommitted changes, unless `--allow-dirty` is given, which is recorded as `code_dirty`;
- a data set this registration has already read, or one that another registration read and this one does not list under `prior_looks`;
- a run directory marked failed, until `--retry-failed` is given.

An incomplete run exits 3 and records nothing, so half an experiment cannot become a result.

## Step 7. What a run would look like, if one were signed

Not run, and not the reader's to run: signing is the owner's step, and the file is committed before the run. The [runbook](../runbooks/registered-experiment.md) has the order: clean checkout, idle machine, output directory outside git, frozen class path, an optional timing-only pilot (`--pilot 4 --timing-only`, which writes and reads no P&L), a detached launch, the status command and nothing else while it runs, then one reading of the ledger. The session files stay closed until the end, because the registration allows one look.

## Step 8. The verdict on the ledger

**Run on 2026-11-24**, while no family has been run:

```bash
PYTHONPATH=research python -m ratesresearch.prereg bh data/ledger/ledger.jsonl family:R5-FAM-001
```

The last line it prints:

```
family family:R5-FAM-001 (q = 0.05): 0 tests from 0 ledger rows
```

After a family run the table gives each hypothesis its p-value, its Benjamini-Hochberg value, its bootstrap interval, whether the guards held, and a verdict: `supported`, `supported if the guards hold` (guards unchecked), `reversed`, `trading less` (a guard failed, whatever the P&L) or `inconclusive`. Whatever it says is a statement about the simulator under declared assumptions (DR-008).

## Knowledge check

1. Why may the smallest difference not be set after the pilot? It would be chosen to make the sample size comfortable, using the data that sizes the sample.
2. Why are 5,000,000 and 8,000,000 refused as bases? They have been generated and read; a second test on read data is a look nobody counted.
3. A result is `supported` and the treatment quotes nine times as many RFQs. What do you write? That it quotes more, with the counts beside the P&L, and that the quoted-share guard could not have failed.
